## Constellations: A Ground-Up Rebuild

This is the star of the show (pun absolutely intended). The old constellation rendering was a single monolithic component. We broke it apart into a clean, modular architecture under `src/three/objects/constellation/`:

### New Architecture

- **ConstellationLayer.tsx** — The top-level orchestrator. Composes nebula clouds, moving background stars, and SVG-outlined constellation motifs into a single scroll-reactive layer. Manages the flash/regeneration lifecycle and the scroll-boost system.
- **MotifInstanceVisual.tsx** — Renders an individual constellation instance: point-stars placed along the SVG contour with twinkle animations, and a thickened SVG outline via a custom GLSL shader. Handles pacman-style toroidal wrapping with up to 9 ghost tiles for seamless edge transitions.
- **MovingStars.tsx** — Background starfield that drifts in sync with the constellation motifs. Stars are distributed across variable depths for a parallax effect.
- **NebulaClouds.tsx** — Soft additive-blend nebula spheres that drift with the field, adding atmospheric depth.
- **placement.ts** — Collision-aware constellation placement with weighted motif selection, edge-biased sampling, and toroidal distance checks. Deterministic PRNG (Mulberry32) ensures consistent layouts per regeneration epoch.
- **schedule.ts** — The "2-6-2" visibility queue: each constellation fades in over 2 seconds, holds for 6, and fades out over 2. Staggered round-robin scheduling ensures a steady rhythm of appearing and disappearing constellations.
- **shaders.ts** — Custom GLSL vertex/fragment shaders for the constellation outline trace effect.
- **svg-guide.ts** — Extracts contour points from SVG files for star placement and outline rendering.
- **utils.ts** — Pure utility functions: wrap, clamp, smoothstep, seeded RNG, colour picking.
- **types.ts** — All TypeScript interfaces for the constellation system.

### Configuration System

All constellation behavior is now data-driven through JSON configs:

- **constellation-config.json** — Global settings: motif counts/weights, visibility ranges, placement spacing, timing (cycle, fade, regeneration), outline thickness, point-star appearance, and a **global warm colour palette** shared by all constellations.
- **Per-motif JSON files** (`phone-logo.json`, `horizontal-logo.json`, `mask-satellite.json`) — Each SVG motif gets its own config for outline thickness/opacity/brightness, size multipliers, tilt ranges, and point-star counts.

### Global Colour Palette

We moved from per-SVG colour arrays to a single global palette in the constellation config. Every constellation now draws from the same pool of 10 bright warm colours — reds, oranges, and golds — chosen specifically for high contrast against the dark background. No more faint or bluish constellations getting lost in the void!

### New Motif: Horizontal Logo

Added `horizontal-logo.svg` as a new constellation motif alongside the existing vertical logo and mask-satellite. It gets the same outline, size, and point-star treatment. The constellation config gives all three motifs equal weight.

### Key Behaviors

- **Scroll-boosted drift** — Scrolling in any direction speeds up the left-to-right constellation drift. A smoothed velocity multiplier prevents jarring speed changes.
- **Pacman wrapping** — Constellations seamlessly wrap from right to left. Ghost tiles appear at domain edges so the transition is invisible.
- **Flash regeneration** — After each cycle, all constellations flash out, regenerate with a new seed, and flash back in.
- **Variable-depth background stars** — Moving stars are distributed across random depth layers, creating a natural parallax effect as they drift.

## Phone Screen Content System

Built a complete DOM overlay system that renders interactive content precisely over the 3D phone's screen:

### Architecture

- **phoneScreenBridge.ts** — Module-level mutable state for R3F-to-DOM communication. The Three.js scene writes pixel-accurate screen bounds and phase values; DOM components read them via `requestAnimationFrame`.
- **PhoneScreenOverlay.tsx** — Generic wrapper that positions children over the phone display using 3D-to-2D projection. Uses CSS container queries (`cqw` units) for responsive sizing.
- **PhoneScreenSplash.tsx** — Phase 1 content: the RUMAD logo (left of title), club name, subtitle, and social media links. Fades in after the phone settles, then fades up and out as you scroll.
- **PhoneScreenInfo.tsx** — Phase 2 content: club description, program cards with 2D SVG icons (Accelerator, Incubator, Events), and additional info. Scrolls with the background via `contentScroll`.
- **usePhoneScreen.ts** — Hook for subscribing to bridge state updates without React re-renders.

### Phone Model Updates

- Phone colour now cycles through dark warm theme colours over a 24-second period using HSL interpolation.
- Glass materials made transparent (0.65–0.7 opacity) for a softer look.
- Phone starts slightly larger (0.45 initial scale, up from 0.35).
- Display material set to flat dark surface — no more red dot artifact.
